# QQ 界面规范与性能验证

## 样式来源

浅色与深色共用 `assets/qq-ui.css`，在 `qq-skin.css`、`qq-dark.css` 之后加载。颜色来自 `theme.json` / `theme-dark.json` 的 `colors`，通过 `--ds-*` 映射到原生语义变量，避免控件各自维护一套文字和背景颜色。

| 用途 | 约定 |
| --- | --- |
| UI 字体 | Segoe UI、Microsoft YaHei UI、PingFang SC、系统无衬线字体 |
| 代码字体 | Cascadia Code、Consolas、SFMono-Regular；编辑器与终端保留原生字体机制 |
| 字号 | 辅助信息 12px、控件 13px、正文 14px、小标题 16px；文档大标题沿用原生层级 |
| 正文行高 | 1.6 |
| 间距 | 4 / 8 / 12 / 16px |
| 皮肤控件 | 常规高度 28px、卡片标题高度 34px |
| 圆角 | 控件 4px、卡片 6px；原生分段开关保留胶囊形状 |
| 焦点 | 2px 主题强调色轮廓 |
| 动效 | 保留原生状态指示，停用皮肤签名的持续跑马灯和装饰浮动 |

这是 QQ 运行界面的共享规范。自定义图片主题、官网和安装器保留各自的呈现，不将桌面定位规则传播到这些界面。

## 原生交互边界

- 右侧文件、浏览器、聊天选项卡由 Codex 管理。皮肤不重建 tab、移动 React 节点或接管新增、关闭、切换、拖动事件。
- 主标题栏保持透明，其固定定位子元素的祖先不使用 `filter` / `backdrop-filter`。皮肤仅预留自身工具栏高度；原生内容框架继续预留原生标题栏高度，侧边选项卡行不重复预留。
- ChatGPT 的“聊天 / 工作”沿用原生网格、滑块 transform、选中状态、键盘和禁用逻辑。按钮本身不再覆盖滑块的背景。
- 摘要、个人资料与设置页继续使用各自的原生或皮肤组件；切回原版时清理皮肤样式和路由标记。

## 性能约束

- 不在 `html` 上用深层 `:has()` 推导路由。由已有路由同步写入 `data-qq-home-route`、`data-qq-settings`、`data-qq-native-shell` 等标记，仅状态变化时写入。
- 流式文本、虚拟列表和皮肤自身的 DOM 更新不触发整页布局同步；实际结构变化、点击和尺寸变化仍及时同步。
- 4 秒心跳只检查状态；30 秒兜底路由同步。隐藏窗口跳过心跳。Quick Chat 的 `data-state` 变化单独触发同步，兼容键盘打开。
- 阅读区域和常驻卡片不使用滚动期间反复采样的毛玻璃。
- `window.__CODEX_QQ_SKIN_STATE__.metrics` 提供累计 ensure 次数、路由次数、布局次数、`ensureTotalMs` 和 `ensureMaxMs`。它们是皮肤自身指标，不代表整个应用帧率。

## 2026-09-17 验证记录

环境：Windows，Codex `26.911.7940.0`，Node `26.3.0`。在当前真实 Electron renderer 经本机 CDP 注入；未修改官方安装包。

确认了浅色/深色、ChatGPT 聊天与工作切换、多个右侧文件 tab、tab 激活和关闭、新增 tab 菜单、侧边面板关闭/重开、个人资料弹窗、摘要与资料卡、设置页。检查了 1922×1034 窗口及 1280×800、1024×768 的模拟视口。浏览器内容保留已有独立 portal 层级修复。

滚动对照：同一会话、文件侧栏、1024×768 视口，注入后等启动同步结束，连续三轮、每轮 8 秒。以相同正弦轨迹改变真实会话容器 `scrollTop`，采集 rAF 间隔、Long Tasks 和 CDP Performance 指标；结束时恢复滚动位置。基线为本次修改前 `63f5732`。

| 每轮指标 | 修改前 | 优化后 |
| --- | --- | --- |
| rAF 回调速率 | 57.69–58.39 FPS | 59.62–59.85 FPS |
| P95 帧间隔 | 16.8 ms | 16.8 ms |
| 大于 34 ms 的帧间隔 | 5–6 | 1 |
| 大于 50 ms 的长任务 | 5–6 | 1 |
| 样式重算累计耗时 | 489–586 ms | 193–222 ms |
| 主线程任务累计耗时 | 1422–1717 ms | 614–635 ms |
| 皮肤完整路由/布局同步 | 2 | 0–1 |

相同窄视口的原版单轮对照约 59.95 FPS，未采到超过 34 ms 的间隔。优化后另外检查了宽窗口浅色与深色，各约 59.8 / 59.6 FPS，P95 均为 16.8 ms，各仍采到 1 个长帧。Trace 显示初轮主要瓶颈是全局关系选择器使数千节点重复计算样式，随后移除这些全局匹配。

这些是特定窗口、内容与负载下的 renderer 测量，包含原生应用活动，不等于物理显示器呈现帧率，也不保证所有机器或极长会话零掉帧。未验证 macOS、高刷新率屏幕或完整退出重启应用。
